RADVOT cinematic motion refinement — local acceptance report
2026-11-04

The existing procedural world, purple portal, Intelligence Core, dialogue,
eight sequences, geometric RADVOT reveal, and interactive demo were preserved.
No dependencies were added. No backend files were modified. No commit, push,
or deployment was performed.

Observed causes and corrections

Continuous scroll progress previously drove React updates and chapter-dependent
canvas layout changes. Native smooth scrolling could also compete with the
scroll-linked animation. Repeated particle meshes increased draw submissions;
hard visibility gates and unsmoothed presentation changes created rough edges.

One GSAP scrub (0.28 seconds) now owns temporal smoothing. Its tween update drives
the scene ref and CSS variables; React receives only chapter, component activation,
and authorization changes. Native scrolling remains intact. Navigation seeks the
same timeline, with no second damping controller. Native CSS smooth scrolling is
disabled only inside the cinematic route.

The canvas keeps stable bounds through the narrative. Camera position, look-at,
zoom, and optical view offset follow continuous authored envelopes. Reframing no
longer resizes the drawing buffer at chapter boundaries. No camera shake or extra
spinning was introduced.

Portal formation and departure retain the original shader and layered rings.
Continuous scale, opacity, and energy envelopes connect formation, materialization,
and dissolution. The core gains restrained floating and light pulsation; ambient
motion slows into silence. Network, connection, beacon, selection, and seed
visibility use continuous envelopes. Traveling pulses shrink at their loop edges.
The six orbital components illuminate progressively, retain deterministic
activation thresholds, and transform into the existing voxel wordmark. Labels
move continuously into the final composition. Copy fades around chapter swaps
with a long readable hold and only one active narrative block.

Performance changes

The full profile's 90 fragments and 28 signals are now two instanced batches
instead of 118 individually rendered meshes. Compact uses 36 + 14 instances.
Geometries/materials are shared, transforms reuse scratch objects, and orbital
origins are precomputed. Static line colors are uploaded once; connection positions
change only with timeline progress. Camera projection updates are similarly gated.
Frame deltas are capped for ambient motion after stalls. Demand rendering stops
when paused, hidden, offscreen, or fully silent.

Profiles cover full, balanced, compact, and economy devices. They vary city detail,
particle counts, ring segments, antialiasing, and maximum DPR while retaining all
essential scenes. Sustained slow frames may reduce DPR in two bounded steps.
Geometries, materials, and instance buffers are disposed on unmount. Browser tests
verify stable buffer creation over replay and zero remaining tracked buffers after
switching to the text edition three times. This is buffer lifecycle evidence, not
a complete GPU memory profiler.

Demo and terminology

Visible content, controls, accessible labels, and page titles use “experience”
or “The Third Force.” Internal identifiers, /story, and handoff parameters remain
compatible. The only change inside DemoApp is the requested empty-state wording;
reversing that string restores its exact pre-edit SHA-256 hash. Engine, data,
planning adapter, styles, and dependencies remain unchanged.

Demo choices preload the existing workspace on focus/pointer intent. Supported
browsers use a short native same-origin view transition; other browsers retain
normal navigation with a dark loading surface. Reduced motion disables that
transition. Cloud/On-Premises handoff and existing session preservation are tested.
This remains a page navigation, not one shared WebGL scene across both routes.

Measurement limits

The initial baseline probe inadvertently used native smooth scrolling on every
animation frame, repeatedly restarting its scroll target. Its settled screenshots
are useful visual references, but its sweep timings are not a valid before/after
performance baseline. No FPS or percentage speedup is claimed. Final measurements
use explicit instant native scroll across a varied forward/reverse path, with
GSAP providing the sole visual smoothing, and run separately from browser tests.

Tests use installed Chrome on this Mac with desktop/tablet/mobile emulation, not
physical mobile hardware or Safari/Firefox. RAF timings measure scheduling
consistency, not GPU execution time. Thermal throttling and longer sessions may
behave differently. The lazy Three.js scene bundle still triggers Vite's >500 kB
warning (840.25 kB minified, 226.92 kB gzip).

GitNexus impact calls could not resolve the website symbols in the enclosing
Github index: risk UNKNOWN. References were inspected manually. Its final change
detection also failed because the enclosing repository has no HEAD. This is not
a clean graph-based impact certification. The 32-file pre-edit hash comparison is
retained in preservation-check.json; unrelated files were preserved.
